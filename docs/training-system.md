# AI 实战学习社区培训体系（验证期）

## 1. 产品定义

第一期是一个 14 天的 Claude Code 实战培训，面向不懂代码、希望用 AI 提升工作效率的职场人。

培训的结业结果是：学员能从一个真实需求出发，使用 Claude Code 搭建自己的 AI 工作空间，完成一个可运行、可交付的小项目，并能说明项目如何运行、如何检查和如何继续改进。

第一期属于培训验证期，目标是验证课程内容、项目路径和用户需求。长期陪跑是后续产品形态，等培训模式验证后逐步加入。

## 1.1 教学语言与讲解标准

课程面向非技术背景的学习者。技术名词不是教学起点，生活中的问题和可观察的结果才是教学起点。

每个概念必须按以下顺序讲解：

1. 先说明学习者会遇到的真实问题。
2. 用生活场景、类比或寓言建立直觉。
3. 让学习者完成一个最小可行操作。
4. 再揭示这个操作对应的正式概念和名称。
5. 解释概念中的每个关键部分，并指出常见误解。
6. 用一个真实工作案例让学习者迁移应用。

复杂概念可以使用寓言式解释：故事先展示人物、冲突和选择，直到结尾才揭示对应的技术概念；故事结束后，再逐一解释隐喻与概念的对应关系。故事用于建立理解，操作练习用于验证理解。

遇到复杂问题时，可以用大白话分析法帮助学员抓住主要矛盾、区分问题类型、安排处理顺序，并通过最小实践验证判断。解释可以借用“抓主要矛盾”“具体问题具体分析”“从实践中来再回到实践中去”等思路，但必须落到学员当前项目的具体行动，不能停留在抽象口号。

项目实践采用“从结果倒推最小可行路径”的方法：先明确要解决的真实问题，再拆出必要条件，删除不必要的步骤，先做能运行和检查的最小版本，用真实输入快速验证，最后才把稳定且值得重复的流程交给 Agent 自动执行。

需要视觉解释时，使用 ELI5 风格：大图、少量文字、一个核心关系，避免把术语堆在图上。课程中的 ELI5 解释应服务于后续操作，而不是替代操作。

### 单课内容模板

- 今天要解决的问题
- 一个生活化故事或场景
- 用一句话说清楚
- 这个东西的正式名称
- 跟着做的最小练习
- 学员自己的真实场景练习
- 如何判断做对了
- 常见误解和排错方法
- 一张小图或一页速查表

### 用词规则

- 第一次出现术语时，先说人话，再括号标出术语。
- 每次只引入完成当前任务所需的词。
- 用“让 AI 记住项目规则”解释上下文管理，用“分工给不同 AI”解释多 Agent，用“给 AI 接上外部工具”解释 MCP。
- 不要求学员背命令；命令只在完成任务时出现，并配有可复制步骤和结果示例。
- 不把“提示词”讲成神秘技巧，而是讲成对目标、背景、限制和验收方式的清楚说明。

## 2. 学习方法

课程采用“项目驱动 + 能力晋级”双维度模型。

- 项目驱动：学员围绕自己的资料和真实工作场景完成项目。
- 能力晋级：每个项目任务都对应一组 AI 使用能力，完成验收后进入下一层级。
- 迁移学习：`llm-wiki` 作为综合案例，学员理解其组织知识、管理上下文和驱动工作流的方法，再迁移到自己的项目。

## 3. 七层能力模型

| 层级 | 能力 | 阶段结果 |
|---|---|---|
| L1 | 环境使用 | 安装 Claude Code，完成账号、代理、充值和基本运行 |
| L2 | AI 协作 | 能向 AI 描述目标、提供上下文并完成单步任务 |
| L3 | 任务指挥 | 能拆解任务，设置约束、输出格式和验收标准，并要求 AI 修正 |
| L4 | 知识管理 | 能组织项目资料、规则和上下文，让 AI 持续理解项目 |
| L5 | 单 Agent 管理 | 能让一个 Agent 按流程独立完成一组任务 |
| L6 | 多 Agent 调度 | 能把复杂工作拆分并分派给多个 Agent，再汇总和验收结果 |
| L7 | Agent 构建 | 能设计、开发、测试和维护自己的 Agent |

第一期主要完成 L1–L4，并让学员体验 L5 的基本形态。L6–L7 放入后续阶段。

## 4. 14 天课程骨架

### 第 1 阶段：环境可用（第 1–2 天）

目标：每位学员拥有可以持续使用的 Claude Code 工作环境。

- Claude Code 安装与更新
- 账号注册、登录和模型选择
- 代理、充值和额度管理
- 终端、目录、文件和 Git 基础
- 第一次让 Claude Code 读取并修改项目文件
- 环境验收：学员独立完成一次任务并保存结果

### 第 2 阶段：与 AI 协作（第 3–5 天）

目标：学员能够让 AI 理解工作目标并完成单步任务。

- 如何描述目标、背景和当前状态
- 如何提供上下文和资料
- 如何限制范围、格式和行为
- 如何要求 AI 先分析再执行
- 如何检查结果并要求修正
- 使用一个小任务完成“需求—执行—检查—修正”循环

### 第 3 阶段：任务指挥（第 6–7 天）

目标：学员能够把模糊需求拆成可执行任务。

- 任务拆解
- 验收标准
- 工作步骤和依赖关系
- 失败处理和回滚
- 把常用要求沉淀为项目规则
- 用一个完整任务验证工作流

### 第 4 阶段：项目知识与 `llm-wiki` 方法（第 8–10 天）

目标：学员能够建立自己的 AI 可读项目资料结构。

- `llm-wiki` 的目录、文档和规则组织方法
- 哪些资料应该进入项目上下文
- 如何写项目说明、规则和操作记录
- 如何让 AI 在多次会话中保持一致理解
- 学员把自己的资料迁移到简化项目结构
- 新增一个自己的项目规则或工作流程

### 第 5 阶段：单 Agent 工作流（第 11–12 天）

目标：学员能够让 AI 按固定流程独立完成一组任务。

- 明确 Agent 的目标、输入、步骤和输出
- 定义允许使用的资料和工具
- 设置验收标准和失败处理
- 让 Claude Code 执行一次完整工作流
- 检查结果、定位问题和迭代规则

### 第 6 阶段：项目交付（第 13–14 天）

目标：学员完成一个自己的可运行、可交付小项目。

- 选择个人真实场景
- 确定项目范围和验收标准
- 完成项目实现
- 现场或线上演示
- 提交项目说明、运行方法和复盘
- 评估下一阶段需要补齐的能力

## 5. 项目分支

所有学员先完成共同的 AI 工作空间和基本工作流，再选择一个分支：

- 内容生产：从资料整理到文章、脚本或营销内容
- 客户研究：从资料收集到客户画像和跟进建议
- 产品资料：从原始资料到结构化产品内容
- 数据整理：从文件清理到报告或表格输出
- 工作自动化：把重复步骤变成可执行流程
- 小型工具：使用 Claude Code 完成一个简单网站或内部工具

## 6. 交付方式

- 线下：安装、关键演示、集中工作、阶段验收和项目展示
- 群聊：进度同步、问题收集和同伴交流
- 文档：课程内容、操作步骤、故障排查、作业和验收标准

第一期不承诺完整的长期陪跑。课程结束后，根据验证结果设计月度项目、助教服务和持续陪跑产品。

## 7. 结业标准

学员需要提交：

- 项目目标和真实使用场景
- 项目资料和规则结构
- 一次完整的 AI 工作流
- 可运行或可交付的项目结果
- 运行方法和验收标准
- AI 执行失败时的处理记录
- 下一步改进计划

## 8. 培训验证指标

- 付费人数
- 第 1 天环境完成率
- 第 7 天任务完成率
- 第 14 天项目完成率
- 结业项目通过率
- 学员将方法迁移到自己工作的比例
- 学员继续学习或购买后续产品的比例
- 各阶段的主要卡点和退出原因

## 9. 后续产品演化

验证期结束后，根据学员反馈逐步加入：

- 月度真实项目
- 项目评审
- 助教和导师支持
- AI 助教
- 按能力层级的进阶课程
- 多 Agent 和 Agent 开发专题

## 10. 完整课程地图

### 阶段一：入门——建立 AI 工作环境

对应 L1–L2。目标是让没有技术背景的人能安全地使用 Claude Code，并完成第一次真实任务。

#### 模块 1：认识 AI 工作助手

- AI 能帮什么忙，不能替你承担什么责任
- Claude Code 和普通聊天工具有什么区别
- 用“助理在你的工作桌旁边”解释 AI 工作环境
- 练习：让 AI 读取一份资料并整理出结果

#### 模块 2：安装与运行

- 安装、登录、账号、模型、额度和代理
- 终端、文件夹和项目，用“工作台、抽屉和资料夹”解释
- 练习：创建项目、启动 Claude Code、保存第一次成果

#### 模块 3：第一次交付

- 如何提出一个清楚的工作要求
- 如何查看 AI 做了什么
- 如何检查结果并让 AI 改进
- 项目：完成一个个人资料整理或小型内容任务

**阶段验收：** 学员能够独立启动 Claude Code，完成一个有输入、有输出、有检查的任务。

### 阶段二：进阶——让 AI 稳定完成工作

对应 L3–L4。目标是让学员从“会问问题”变成“会交代工作”。

#### 模块 4：把模糊想法变成工作任务

- 先说目标，再说背景，再说限制
- 把大任务拆成几步小任务
- 为每一步写清楚完成标准
- 用“项目经理交代任务”解释任务指挥

#### 模块 5：提示词就是清楚的工作说明

- 目标、背景、资料、限制、输出和验收
- 为什么同一个问题说法不同，结果会不同
- 如何给 AI 反馈和要求返工
- 项目：把一个真实工作任务写成可重复执行的说明

#### 模块 6：让 AI 记住项目规则

- 项目资料、规则、模板和历史记录
- 用“新员工入职手册”解释项目上下文
- 如何避免每次重新解释同一件事
- 项目：创建自己的项目说明和规则文件

#### 模块 7：用 `llm-wiki` 组织工作资料

- 观察 `llm-wiki` 如何组织资料和工作流程
- 哪些内容需要长期保存
- 如何把自己的资料迁移成 AI 看得懂的结构
- 如何让 AI 在多次会话中保持一致
- 项目：搭建自己的简化 AI 工作空间

**阶段验收：** 学员能够把一个真实工作任务拆解成流程，并让 AI 按自己的资料和规则稳定完成。

### 阶段三：高阶——让 AI 按流程自己工作

对应 L5–L6。目标是让学员从一次性使用 AI，升级为设计一套可重复的工作流程。

#### 模块 8：认识 Agent

- 用“把一项工作交给助理”解释 Agent
- 目标、输入、步骤、权限、输出和验收
- 为什么 Agent 需要边界和检查
- 项目：让一个 Agent 完成一项固定工作

#### 模块 9：Skills 和可重复工作

- 用“工作手册”解释 Skill
- 把常用要求整理成可以重复使用的步骤
- 如何判断一项工作是否值得整理成 Skill
- 项目：为自己的工作创建一个简单 Skill

#### 模块 10：多个 AI 如何分工

- 用“一个负责人带几个专员”解释多 Agent
- 哪些任务适合分工，哪些任务适合一个 Agent 完成
- 任务分派、结果汇总和互相检查
- 项目：把一个复杂任务拆给多个角色完成

#### 模块 11：给 AI 接上外部工具

- 用“给助理钥匙和工具柜”解释 MCP
- AI 如何使用文件、网页、数据库或其他服务
- 权限、隐私和安全边界
- 项目：让 Agent 使用一个外部工具完成工作

**阶段验收：** 学员能够设计一套有边界、有检查、可重复运行的 Agent 工作流。

### 阶段四：专家——构建自己的 AI 系统

对应 L7。目标是让学员能够把稳定的工作流程发展成可维护的 AI 产品或团队系统。

#### 模块 12：Agent 的设计和开发

- 如何定义 Agent 的职责
- 如何设计输入、输出和失败处理
- 如何拆分工具和工作步骤
- 如何测试 Agent 是否稳定

#### 模块 13：自动化与团队协作

- 什么时候可以自动运行
- 如何记录过程和结果
- 如何让团队共享规则、Skills 和项目资料
- 如何进行版本管理和变更检查

#### 模块 14：质量、安全和成本

- 如何发现 AI 的错误和幻觉
- 如何设置权限和保护敏感资料
- 如何减少重复输入和不必要的消耗
- 如何选择合适的模型和工作方式

#### 模块 15：最终系统项目

- 选择一个真实业务流程
- 从结果倒推最小可行版本
- 设计并实现 Agent 系统
- 用真实数据测试
- 记录失败、修正和成本
- 进行最终演示和复盘

**阶段验收：** 学员能够交付一个可运行、可解释、可维护的 AI 工作系统。

## 11. 项目实践的统一方法

所有阶段都使用同一套项目推进方法：

1. 说清楚最终要解决的问题。
2. 找出真正必要的资料、步骤和工具。
3. 删除没有必要的功能和流程。
4. 先做能运行、能检查的最小版本。
5. 用真实输入快速验证。
6. 先修正最影响结果的问题。
7. 流程稳定后，再交给 Agent 自动执行。

每个项目必须提交：目标、最小版本、操作步骤、验收方式、失败记录和下一步改进。

## 12. 项目难度分层

| 项目等级 | 适合阶段 | 项目特征 |
|---|---|---|
| A | 入门 | 一次输入、一次处理、一次输出 |
| B | 进阶 | 多份资料、固定规则、需要检查和返工 |
| C | 高阶 | 多步骤流程、单 Agent、自定义 Skill 或外部工具 |
| D | 专家 | 多 Agent、自动运行、团队协作或业务系统 |

## 13. 每个项目的验收表

- 学员能否用自己的话说明要解决的问题？
- 输入资料是否完整且来源清楚？
- AI 是否按规定步骤执行？
- 输出是否符合验收标准？
- 学员能否发现错误并要求修正？
- 项目能否重复运行？
- 学员是否知道下一步该改进什么？

## 14. 课程内容资产

每个模块都应逐步形成以下资产：

- 一篇白话讲义
- 一个生活故事或类比
- 一张 ELI5 风格关系图
- 一份可复制的操作步骤
- 一个最小练习
- 一个真实场景练习
- 一份常见问题和排错表
- 一份验收标准
- 一个失败案例和修正记录

这套资产结构能让课程从一次性讲解，逐步变成可复用、可更新和可交付的培训产品。
